## Findings

### 1. `CHANGELOG.md` — Unreleased carried no entry for the new CI invariant *(fixed)*

Harness resets `CHANGELOG.md` to HEAD before committing implementer work, so a task that adds a
user-visible CI gate lands with no changelog line by construction; closing that is the audit's job
(same fix as `540605b` made for the README gate). Added an Unreleased bullet describing invariant 6,
the AST-based registration source, and its relationship to the README-example gate — README gate
covers `README.md`, this one covers the module docs `ex_doc` publishes.

### 2. `CLAUDE.md` / `AGENTS.md` — "Review Blind Spots" invariant list was stale *(fixed)*

`lib/delta_calc/manifest.ex` was updated to six invariants; `CLAUDE.md` § *Review Blind Spots →
Cross-module global invariants* still listed three (name+arity uniqueness, registration, `:hints`),
having already missed invariants 4 and 5. That list is the version the **cross-family reviewer**
reads — it is generated into `AGENTS.md` — so a stale list is the one place where this drift has
teeth: a reviewer cannot reject a diff against an invariant it has not been told exists. Rewrote it
to name all six, and regenerated `AGENTS.md` via
`~/.claude/plugins/marketplaces/zenhive/scripts/sync-agents-md.sh` (`--check` now passes).

### 3. Two documented lib modules sit outside the gate *(filed as task 59, not fixed here)*

Scoping the gate to `Manifest.modules()` is what task 58's criteria allowed, and it is nearly
airtight because invariant 5 forces every publicly documented `lib/delta_calc/` module into
`@modules`. It has exactly two carve-outs:

- `DeltaCalc` (`lib/delta_calc.ex`) is outside the `lib/delta_calc/` directory
  `documented_modules_from_lib/0` scans and is absent from `@modules`. It is covered today only
  incidentally, by a `doctest DeltaCalc` in `test/delta_calc_test.exs` that registers **zero**
  examples (the suite's 2 doctests are both `FundingProjection`'s).
- `DeltaCalc.Manifest` is `Enum.reject`ed by name in `documented_modules_from_lib/0`, so it is
  documented yet ungated by both invariant 5 and invariant 6.

An `iex>` example added to either — the library's front door and the agent-surface entry point —
would not be gated by the invariant built to catch precisely that.

Coupled to it: `doc_examples?/1` tests `String.contains?(doc, "iex>")`, which matches a *prose
mention* as readily as an example. `DeltaCalc.Manifest`'s moduledoc now literally contains the
string (invariant 6's own wording), so widening the gated set without anchoring the detector to an
example line turns CI red immediately. The two halves must land together, which is why this is a
task rather than an inline audit fix.

**Not a correctness bug in what landed.** The detector's error direction is safe: a prose mention
can only produce a spurious *failure*, never a silent pass, so nothing currently advertised is
under-enforced.

→ Filed as **task 59** (`contract_hardening`, phase 3, d2/b3/u2, codex / gpt-6-astra).
