## Finding — lying test (Codex out-of-bundle note + critical-rules violation, pri 7) → FIXED

The commit rewrote the Calc.liquidation differential assertion to:

    assert within_bound or match?(:ok, IO.warn("... exceeds loose bound ..."))

`IO.warn/1` always returns `:ok`, so `match?(:ok, ...)` is always true → the assertion is
`assert within_bound or true` = always passes. The test became structurally incapable of failing:
if Calc.liquidation/4 regressed so the error blew past the loose bound, the test would still pass
and merely print a warning. This is the exact anti-pattern `critical-rules.md` § NEVER HIDE TEST
FAILURES forbids ("a catch-all that makes every outcome pass… is lying"). It also dropped the
`assert length(intervals) >= 2` coverage assertion in the cadence-coverage test.

The change's *intent* (don't hard-gate CI on a documented approximation) is legitimate, but the
implementation lies — and a differential oracle that cannot fail provides zero signal.

**Resolution (per user decision — "real assertion vs loose bound"):** restored a real gating
assertion `assert Decimal.compare(error_pct, bound) != :gt` with a descriptive failure message.
The fixture's loose bound (1.0%) already gives ~3× headroom over the actual error (~0.30%), so the
gate is generous but honest — gross regression past the loose bound now fails CI as it should.
Test renamed back to drop the "(informational)" qualifier.
