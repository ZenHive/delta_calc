## Findings

### 1. `.mcp.json` tidewave port drift (config bug) — FIXED

Commit `45f01da` ("point tidewave MCP at :4025 + add dashboard_tidewave server")
repointed delta_calc's **own** `tidewave` MCP server from `:4024` to `:4025`,
making it an exact duplicate of the newly-added `dashboard_tidewave` (both
`http://localhost:4025/tidewave/mcp`). This contradicts three sources of truth
that all agree on **4024** for delta_calc:

- `~/.claude/tidewave-ports.md` registry: `4024 → delta_calc` (standalone
  Bandit), `4025 → trading_dashboard` (a separate Phoenix app).
- `mix.exs` `tidewave` alias starts Bandit on **4024** — nothing in this repo
  serves 4025.
- `CLAUDE.md` / `AGENTS.md` § Tidewave: "`mix tidewave` (port **4024**); the
  `.mcp.json` `tidewave` server points there."

Effect: the project's own `mix tidewave` node (4024) was unreachable via MCP, and
the duplicate 4025 entry was redundant. The `dashboard_tidewave → 4025` entry is
correct (the trading_dashboard node has both `ccxt_client` and `delta_calc`
compiled — the fixture-refresh node the new README points at).

**Fix:** restored `tidewave` → `http://localhost:4024/tidewave/mcp`, keeping
`dashboard_tidewave` → 4025. Config now agrees with registry + mix.exs + CLAUDE.md.
