## Finding — inverted `min_delta` raw→daily scaling (filed as task 37)

`threshold_for_delta_unit/2` scales `min_delta` for `:daily_normalized` entries by
**dividing** by `@default_periods_per_day` (`min_delta / 3`). Dimensional analysis says this is the
wrong direction:

- The daily-normalized delta is `raw_rate * periods_per_day` — **larger** than a raw per-period
  spread, not smaller.
- To express a raw per-period `min_delta` on that same daily basis, you **multiply** by periods.
- **Decisive internal evidence:** the same daily code path normalizes its arbitrage gate raw→daily
  by *multiplying* — `@mixed_cadence_arbitrage_threshold = @arbitrage_threshold * @default_periods_per_day`
  (`0.0005 * 3 = 0.0015`), with a docstring calling it "the default 8-hour raw threshold normalized
  to daily terms." So the file converts raw→daily with `×periods` for the arbitrage threshold but
  `÷periods` for `min_delta` — contradictory directions for the identical conversion, three
  functions apart.

Consequence: daily-normalized entries pass `min_delta` filtering ~9× more permissively than the
stated goal ("filter scalar- and map-cadence results together without scale skew") intends.

This is the **domain-ground-truth blind spot** described in `CLAUDE.md` § "Review Blind Spots":
internally consistent, fully tested, reviewer-approved, still wrong. The root cause traces upstream
to task 36's own `body`, which framed the original bug as "threshold ~3x too large" and illustrated
the map delta as `0.0003` (smaller than raw) — both dimensionally backwards. The implementer
faithfully encoded the backwards premise, and the golden test (`min_delta 0.0045 → threshold 0.0015`)
was computed *with* the inverted scaling, so coverage ratifies it rather than catching it.

**Not fixed in this audit by design.** Reversing the scale direction is a behavior change that
rewrites a reviewer-ratified golden test; it belongs in a properly-scoped, re-dispatched task with
the dimensional invariant written into acceptance criteria — not a unilateral audit edit. The audit
never reverts or blocks. Filed as **task 37** (`depends_on = [36]`) with the dimensional reasoning
and a re-derive-from-first-principles acceptance criterion.
